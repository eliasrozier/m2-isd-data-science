# Data Science project — choose your subject

Four days: three working days (two sessions of 3h30 each) and a defence. You **build a pipeline of
several models**, improve it **day after day**, and decide with **measurements**: how much quality do you
get for a given latency, energy or hardware budget? You will not train big models; you will select,
combine, configure and benchmark existing ones, and defend your choices.

| | Project S — Speech recognition | Project X — (external lecturer) |
|---|---|---|
| Question | How much does language knowledge add to acoustic evidence, what does it cost, and what would you deploy on a laptop for a push-to-talk assistant? | |
| Day 1 | classical recogniser: MFCC, GMM-HMM, n-gram language models, Viterbi decoding | |
| Day 2 | neural recognisers (Whisper, wav2vec2, …) + external language models | |
| Day 3 | choose a deployment from your Pareto fronts; plug your systems into a live browser demo next to an on-device reference | |
| You implement | Pareto filter, n-gram LMs, Viterbi with an LM, benchmark loop, CTC decoding, streaming policy | |
| Compute | laptop CPU is enough; a GPU only speeds up the large models | |
| Good fit if you like | probabilistic models, signal processing, NLP, building things that work live | |

Same rules for every subject: groups of 3-4 · one delivery at the end of each day · a decision log you
defend orally on the last day (half of the grade) · any tool allowed, LLMs included: you are
responsible for everything you submit.
